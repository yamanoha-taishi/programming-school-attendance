# PR の説明文（動作確認つき）

## 1. 変更を集める

```bash
git branch --show-current
git log --oneline origin/main..HEAD
git diff --stat origin/main...HEAD
```

- 変わったファイルを、画面（`web/resources/js/pages/`）・部品（`components/`）・ルート（`web/routes/`）・コントローラー・テスト・設計書（`docs/`）に分ける
- 説明文のひな形は `.github/pull_request_template.md`。見出しの順番を変えない
- すでに PR があるときは `gh pr view --json body -q .body` で今の説明文を読み、足りないところだけ直す

## 2. 動作確認の項目を作る

変更の中身から、確かめるべき項目を作る。決まった項目を並べるのではなく、この PR で変わったところごとに書く。

| 変わったもの | 書く項目の例 |
|---|---|
| 画面・部品 | どの画面の、どの表示・操作か（「管理メニューの行を押すと保護者一覧へ進む」など） |
| 見た目 | デザイントークン定義書の決まりどおりか（高さ44px以上、色、文字の大きさなど） |
| ルート・コントローラー | 権限ごとに開ける・開けない（full_access・attendance_only・保護者。403 やログイン画面へ戻るなど） |
| 保存・更新 | 保存できる、エラーのときのメッセージ、記録が消える操作の確認 |
| 画像・ファビコンなど | どこで表示を確かめたか |

- 画面の確認は、PC の Chrome のデベロッパーツールで幅 375px（iPhone SE）にして行う。スマホの実機での確認はしない（必要なら「確かめていないこと」に書く）
- 項目は、ユーザーが読んで同じ操作ができる具体的な文にする

## 3. 実際に確かめる

- `bash scripts/check.sh` を実行して、結果を「自動のチェック」に書く
- 画面の項目は、できるものはブラウザで実際に開いて確かめる
- **確かめたものだけ `[x]` にする。** 確かめていないもの・確かめられなかったものは `[ ]` のまま残し、「確かめていないこと」に理由を書く（「ブラウザで開けなかった」「保護者の画面がまだ無い」など）
- 推測で `[x]` にしない。テストで確かめた項目は、テスト名を添える

## 4. 説明文を書いて、PR を作る・直す

- 日本語（平易な日本語）で書く
- 説明文はファイルに書いてから渡す（長い文をコマンドに直接入れない）

```bash
gh pr create --base main --title "<タイトル>" --body-file <説明文のファイル>   # 新しく作るとき
gh pr edit <番号> --body-file <説明文のファイル>                              # 直すとき
```

- 説明文のファイルは、リポジトリの外か `memo/` に置き、コミットしない

## 5. 報告

PR の URL と、確かめていない項目（あれば）を短く伝える。レビューは、ユーザーに頼まれたときだけ `pr-review` スキルで行う（ここでは始めない）。
