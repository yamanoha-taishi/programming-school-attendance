# PR のレビュー

## 1. 対象を決める

```bash
git branch --show-current
gh pr view --json number,title,url -q '.number, .title, .url'
```

- PR が無いときは止めて、先に PR を作るか（`pr-description` スキル）ユーザーに聞く
- 未コミット・未プッシュの変更があるときは、ユーザーに伝える（レビューはプッシュ済みの差分に対して行う）

## 2. サブエージェントにレビューさせる

`pr-reviewer` サブエージェントを呼び、PR の番号を渡してレビューさせる。

- 書いたときの会話の内容（なぜそう書いたか）は渡さない。差分と設計書だけで判断させるため
- 自分（呼び出した側）でレビューの中身を足したり消したりしない。返ってきた結果をそのまま使う

## 3. PR にコメントする

レビュー結果をファイルに書いてから、PR にコメントする。ファイルは `memo/` かリポジトリの外に置き、コミットしない。

```bash
gh pr comment <番号> --body-file <レビュー結果のファイル>
```

- コメントの先頭に「Claude Code（pr-reviewer）によるレビュー」と書く

## 4. 報告

- 「直した方がいい点」「確認したい点」を、ユーザーに短く伝える
- **直すかどうかはユーザーが決める。** 聞かずに直さない
- 直したあとは、もう一度このスキルでレビューしてよい（直した点だけ見るよう伝える）
