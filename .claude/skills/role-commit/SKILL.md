# 役割ごとのコミット

## 1. 変更を確かめる

```bash
git branch --show-current
git status --short
git diff --stat
git log --oneline -5      # メッセージの書き方を合わせるため
```

- 今のブランチが `main` なら、コミットせずに止めて、作業用のブランチを作るかユーザーに聞く
- 秘密の情報が入りそうなファイル（`.env`、`*.key`、`settings.local.json` など）は入れない。入っていたらユーザーに伝える

## 2. 改行コードだけ変わったファイルを外す

変更されたファイルごとに確かめる。終了コードが 0 なら改行コードだけの変更なので、**コミットに入れない**。

```bash
git diff --ignore-cr-at-eol --quiet -- <ファイル>
```

外したファイルは、最後の報告で「改行コードだけの変更なので入れなかった」と一覧で伝える（元に戻すことはしない）。

## 3. 役割ごとに分ける

| 種類 | 使うとき |
|---|---|
| `feat:` | 機能を足す・変える |
| `fix:` | 不具合を直す |
| `test:` | テストだけを足す・直す |
| `docs:` | ドキュメント（`docs/`、`CLAUDE.md`、`README` など）だけ |
| `style:` | 動きを変えない見た目・整形（インデント、Pint・Prettier の結果など） |
| `refactor:` | 動きを変えずにコードを整理する |
| `chore:` | 設定・ツール・依存パッケージなど |

- 1つのコミットには1つの役割だけ入れる。機能とそのテストは、まとめても分けてもよい（このリポジトリの過去のコミットに合わせる）
- 1つのファイルに別の役割の変更が混ざっているときは、無理に分けずに主な役割にまとめ、報告で伝える
- コミットの数と中身の案を、先にユーザーへ短く見せてからコミットする（ユーザーが「そのままコミットして」と言っていれば省いてよい）

## 4. コミットする

- `git add` はファイル名を1つずつ指定する。`git add .`、`git add -A`、`git add -u` は使わない
- メッセージは「`種類: `」の後に、何をしたかを日本語で1行。最後に空行と Co-Authored-By の行を付ける

```bash
git add web/app/Http/Controllers/Foo.php web/routes/web.php
git commit -m "$(cat <<'EOF'
feat: 授業回の一覧に授業クラスの絞り込みを足す

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
EOF
)"
```

- コミットのフック（あれば）が失敗したら、`--no-verify` で飛ばさずに原因を直す

## 5. プッシュする

```bash
git push -u origin <今のブランチ>
```

- `main` へのプッシュと強制プッシュ（`--force`、`-f`、`--force-with-lease`）はしない。必要そうなら止めてユーザーに聞く
- プッシュが拒否されたら（リモートが先に進んでいるなど）、強制せずにユーザーに伝える

## 6. 報告

作ったコミット（`git log --oneline` の該当部分）、プッシュ先、入れなかったファイルを短く伝える。
