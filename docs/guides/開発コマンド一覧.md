# 開発コマンド一覧

- 作成日：2026-10-07
- 更新日：2026-10-07

開発中に日常的に使うコマンドをまとめる。

## 前提

- コマンドは`web`フォルダ（`docker-compose.yml`がある場所）で実行する
- PHP・Laravelのコマンドは`app`コンテナ、npm・Node.jsのコマンドは`node`コンテナで実行する。どちらも`docker compose exec <コンテナ名> <コマンド>`の形になる
- Windows側のターミナルで直接`npm run ...`を実行すると、`tsc`などが見つからずエラーになる（npmのパッケージは`node`コンテナの中にだけ入っているため）。必ず`docker compose exec node`を付ける

## PHP側（`app`コンテナ）

| やりたいこと | コマンド | 中身 |
|---|---|---|
| Pint（PHPの書き方を整える） | `docker compose exec app composer lint` | `pint --parallel`。ファイルを自動で直す |
| Pint（確認だけ） | `docker compose exec app composer lint:check` | 直さずに、ルール違反があるかだけ表示する |
| PHPStan（PHPの型チェック） | `docker compose exec app composer types:check` | `phpstan analyse`。レベル7で型の間違いを探す |
| テスト | `docker compose exec app php artisan test` | 全テストを実行する |
| テスト（絞り込み） | `docker compose exec app php artisan test --filter=AttendanceUpdateTest` | クラス名・メソッド名が一致するテストだけを実行する |
| PHP側をまとめてチェック | `docker compose exec app composer test` | Pint（確認だけ）→ PHPStan → テストを順番に実行する |

## フロント側（`node`コンテナ）

| やりたいこと | コマンド | 中身 |
|---|---|---|
| Prettier（見た目の整形） | `docker compose exec node npm run format` | `prettier --write resources/`。改行・インデント・クォートなどを自動で整える |
| Prettier（確認だけ） | `docker compose exec node npm run format:check` | 直さずに、整っていないファイルを表示する |
| ESLint（書き方・間違いの検出） | `docker compose exec node npm run lint` | `eslint . --fix`。importの順番など、直せるものは自動で直す |
| ESLint（確認だけ） | `docker compose exec node npm run lint:check` | 直さずに、問題を表示する |
| 型チェック（TypeScript） | `docker compose exec node npm run types:check` | `tsc --noEmit`。型の間違いを探す（ファイルは作らない） |

ESLintとPrettierは役割が違う。

- **ESLint**：コードの中身を見る（使っていないimport、importの順番、Reactの書き方の間違いなど）
- **Prettier**：コードの見た目だけを整える（1行80文字で折り返す、JSXの属性をダブルクォートにそろえるなど）

## コミット前の順番

自動で直すコマンドを先に実行し、そのあとで確認だけのコマンドを実行する。上から順に1つずつ実行する。

### PHPを変更したとき

```bash
docker compose exec app composer lint
```

```bash
docker compose exec app composer test
```

### フロントを変更したとき

```bash
docker compose exec node npm run format
```

```bash
docker compose exec node npm run lint
```

```bash
docker compose exec node npm run types:check
```

## その他よく使うコマンド

| やりたいこと | コマンド | 補足 |
|---|---|---|
| DBを作り直してデモデータを入れる | `docker compose exec app php artisan migrate:fresh --seed` | 全テーブルを削除してマイグレーションをやり直し、Seederを実行する。DBのデータはすべて消える |
| tinkerを開く | `docker compose exec app php artisan tinker` | Laravelのモデルやコードを対話的に試せる。終了は`exit` |
| ルートを確認する | `docker compose exec app php artisan route:list --name=admin.attendances` | `--name`はルート名で絞り込む。URLで絞り込む`--path`だと、`/admin/lessons/...`のようにURLが違うルートが出てこないことがある |

## 注意

- `composer ci:check`は、PHP・フロントのチェックをまとめて実行するコマンドだが、中で`npm`を使うため、`npm`が入っていない`app`コンテナでは失敗する。GitHub Actions用のコマンドとして扱い、ローカルでは上の「コミット前の順番」のコマンドを使う
