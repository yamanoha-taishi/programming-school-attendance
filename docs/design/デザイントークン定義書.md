## 方針

- **雰囲気**：運営スタッフ・保護者が日常的に使う業務ツールである点を優先し、信頼感・使いやすさを軸にする。ただし子供向けプログラミング教室のアプリという背景もあるため、アクセントカラーに温かみのあるオレンジを少量だけ使い、堅すぎない印象に調整する
- **ダークモード**：非対応（ライトモードのみ）。MVPとしてスコープを抑える。スターターキットのダークモード切り替え処理は無効化済み（「Tailwind 4 での実装」の「4. ダークモードの無効化」参照）
- **フォント**：Webフォントは導入せず、端末標準フォント（システムフォント）のみを使用する

## カラートークン

### ベースカラー

| トークン名 | 用途 | HEX |
|---|---|---|
| primary | ボタン・リンク・アクティブ状態など操作の基準色 | `#2E5AAC` |
| primary-hover | primaryのホバー・押下時 | `#24457F` |
| primary-tint | 選択中タブの背景など、淡い強調 | `#E8EEFA` |
| accent | ここぞという箇所のみに使う強調色（多用しない） | `#E8823C` |
| accent-hover | accentのホバー・押下時 | `#C86A28` |
| accent-tint | お知らせ・バッジなどの淡い背景 | `#FCEADA` |

### ニュートラル

| トークン名 | 用途 | HEX |
|---|---|---|
| page-bg | 画面全体の背景 | `#F4F5F7` |
| surface | カード・入力欄などの背景 | `#FFFFFF` |
| border | 区切り線・枠線 | `#DCE0E5` |
| text | 見出し・本文の文字色 | `#1F2430` |
| text-muted | 補足・ラベルの文字色 | `#5B6472` |
| text-faint | プレースホルダー・無効状態の文字色 | `#8A93A0` |

primaryと同じ青みをわずかに含んだグレーにし、統一感を持たせている。

### 出席ステータス（6状態）

要件定義書5.1の出席記録ステータス（通常出席／遅刻／欠席／振替済み／30分前補講済み／未定）に対応。

| ステータス | 文字色 | 背景色 |
|---|---|---|
| 通常出席 | `#2F9E4F` | `#E8F7EC` |
| 遅刻 | `#B08000` | `#FBF3DC` |
| 欠席 | `#D6483F` | `#FBEAE8` |
| 振替済み | `#1E8A8A` | `#E4F5F5` |
| 30分前補講済み | `#7A4FC9` | `#F1EBFB` |
| 未定 | `#767C87` | `#EEEFF1` |

**注意（アクセシビリティ）**：出席／欠席は色覚特性によっては区別しにくい組み合わせ（緑・赤）を含むため、一覧画面では必ず色だけでなくラベルテキスト（「通常出席」「欠席」など）とセットで表示し、色のみで状態を判別させない実装にする。

**ステータス色の使い方（バッジ・選択ボタン共通ルール）**：バッジ（出席記録・一覧の状態表示）だけでなく、出席／欠席を選ぶボタンの選択中スタイルなど、面積の大きいUI要素にステータス色を使う場合も、必ず「淡い背景色＋同系統の文字色」の組み合わせ（例：欠席＝背景`#FBEAE8`・文字`#D6483F`）を使い、彩度の高い色をベタ塗りしない。特に赤（欠席）は面積が大きいと強すぎる印象になりやすいため注意する。選択中であることは、背景色ではなく縁取り（同系色のborder）と太字で示す。

**危険色（status-absentの赤系）を使ってよい場面**：保護者・生徒・スタッフの削除／退会など、データが失われる・元に戻せない操作のボタンにのみ、淡い赤系（背景`#FBEAE8`・文字`#D6483F`、ベタ塗りしない）を使う。ログアウトのような「取り消せるが確認が要る」操作は破壊的操作ではないため、警告色を使わずニュートラル（`border`＋`text-muted`）にする。

## Tailwind 4 での実装

`web/resources/css/app.css` に反映済み。

スターターキットの部品（`Button`・`Input`など）は、`:root`に定義されたCSS変数（`--primary`など）を参照しており、`@theme`の`--color-primary: var(--primary);`のような行でTailwindのクラス名（`bg-primary`など）に結びつけている。このため、トークンの種類によって次の2通りの方法で反映している。

### 1. スターターキットに同じ役割の変数があるトークン：`:root` の値を差し替え

`:root`の値を差し替えることで、スターターキットの既存部品にもそのまま配色が反映される。

| 本定義書のトークン | `:root` の変数 | Tailwindのクラス例 |
|---|---|---|
| page-bg | `--background` | `bg-background` |
| surface | `--card` `--popover` | `bg-card` `bg-popover` |
| text | `--foreground` `--card-foreground` `--popover-foreground` | `text-foreground` |
| text-muted | `--muted-foreground` | `text-muted-foreground` |
| primary | `--primary` | `bg-primary` `text-primary` |
| （primary上の文字色：`#FFFFFF`） | `--primary-foreground` | `text-primary-foreground` |
| border | `--border` `--input` | `border-border` `border-input` |
| primary（フォーカス時の枠） | `--ring` | `ring-ring` |
| status-absent（エラー表示） | `--destructive` `--destructive-foreground` | `text-destructive` |

`--secondary` `--muted` `--accent` `--chart-*` `--sidebar-*` `--radius` はスターターキットの初期値のまま残している。特に`--accent`は、スターターキットでは「メニューなどのホバー時の薄い背景色」の意味で使われており、本定義書のaccent（オレンジ）とは別物のため差し替えない。

### 2. スターターキットに無いトークン：`@theme` に追加

```css
@theme {
    /* （スターターキット既存の --color-xxx: var(--xxx); の行は省略） */

    --color-primary-hover: #24457f;
    --color-primary-tint: #e8eefa;
    /* 定義書の accent。スターターキットの --accent（ホバー背景）と衝突するため brand- を付ける */
    --color-brand-accent: #e8823c;
    --color-brand-accent-hover: #c86a28;
    --color-brand-accent-tint: #fceada;
    --color-text-faint: #8a93a0;

    --color-status-attend: #2f9e4f;
    --color-status-attend-bg: #e8f7ec;
    --color-status-late: #b08000;
    --color-status-late-bg: #fbf3dc;
    --color-status-absent: #d6483f;
    --color-status-absent-bg: #fbeae8;
    --color-status-transfer: #1e8a8a;
    --color-status-transfer-bg: #e4f5f5;
    --color-status-makeup: #7a4fc9;
    --color-status-makeup-bg: #f1ebfb;
    --color-status-pending: #767c87;
    --color-status-pending-bg: #eeeff1;
}
```

これにより`bg-primary-hover` `bg-brand-accent-tint` `text-status-attend` `bg-status-attend-bg`のようなユーティリティクラスが使える。

**名前の対応に注意**：本定義書の`accent`／`accent-hover`／`accent-tint`は、Tailwind上では`brand-accent`／`brand-accent-hover`／`brand-accent-tint`という名前になる。`bg-accent`と書くとスターターキットのホバー背景色（薄いグレー）になるため、オレンジを使うときは必ず`brand-accent`を使う。

### 3. フォント

`@theme`の`--font-sans`を本定義書のフォントスタックに差し替えた。あわせて、スターターキットが初期状態で読み込んでいたWebフォント（Instrument Sans）の設定を削除した（`vite.config.ts`の`fonts`指定と、`resources/views/app.blade.php`の`@fonts`）。

### 4. ダークモードの無効化

スターターキットは、OSの設定や外観設定画面の選択に応じて`<html>`に`dark`クラスを付け、`app.css`の`.dark { ... }`の配色に切り替える作りになっている。方針の通りライトモードのみとするため、`dark`クラスを付ける次の処理を削除した。

- `resources/views/app.blade.php`：`<html>`の`@class(['dark' => ...])`と、OSのダークモードを判定するインラインスクリプト
- `resources/js/app.tsx`：`initializeTheme()`の呼び出し

あわせて、`app.blade.php`のインラインスタイルにある`html`の背景色を、page-bg（`#f4f5f7`）に合わせた（ページ表示直後のちらつき防止）。

`app.css`の`.dark { ... }`ブロック、外観設定画面（`settings/appearance`）と関連ファイル（`use-appearance.tsx`、`appearance-tabs.tsx`、`HandleAppearance.php`など）は残っている。これらはプロフィール設定画面の実装時に、スターターキットの設定画面とあわせて整理する。
