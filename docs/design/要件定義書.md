# 要件定義書

- 作成日：2026-08-11
- 更新日：2026-08-19

## 1. 概要

**テーマ**：子供向けプログラミング教室の出席管理アプリ

**利用者**：教室運営者、保護者

**背景**：開発者自身がプログラミング教室で勤務しており、出席管理をスプレッドシートで行っているが、管理方法に課題を感じ、改善の余地があると考えた。

**目的**：スプレッドシートでの出席管理における課題を解消し、欠席・遅刻・振替・補講の連絡と記録を一元管理できるアプリを構築する。

## 2. 対象ユーザー

- **運営**：保護者・生徒情報の登録管理、出席記録の管理を行う。権限は2種類あり、出席管理のみ行える権限（アルバイトなどを想定）と、出席管理＋生徒・保護者の登録も行える権限（正社員などを想定）に分かれる
- **保護者**：欠席・遅刻・振替・補講の連絡、基本情報の登録・編集、出席履歴・予定の確認を行う

## 3. 前提条件

- 授業は基本週1回実施
- GW・お盆・年末年始など、授業を行わない休み期間がある
- 授業クラスは大きく2つに分かれる
  - クラスA：4歳〜小学2年生向け。さらに3つの授業クラス（A1／A2／A3）に分かれ、それぞれ別日程で授業を実施する
  - クラスB：小学3年生~中学3年生向け。さらに6つ程度の授業クラス（B1〜B6）に分かれる。1つの授業クラスは、同じ授業内容（授業回）を複数の授業実施単位（sections）に分けて実施することがある（授業実施単位あたりの定員が6名までのため）。B1〜B6の授業実施単位は名称を「B」で統一する（曜日・時間帯が異なる複数の「B」が存在し得る）
- ポートフォリオ上の表示名（デモデータ）は、クラスAを「基礎クラス」、クラスBを「応用クラス」とする
- 授業クラスの内部コード（`code`列など）はハイフンなしの英数字（A1／A2／A3／B1〜B6）とし、画面表示名（例：「基礎クラス1組」）とは分けて管理する
- 1つの授業実施単位（sectionsの1レコード）あたりの定員は6名までとする

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| 欠席 | 授業を1回休むこと |
| 遅刻 | 授業に遅れて出席すること。時間通りの出席・遅刻しての出席は同じ「出席」として扱うが、遅刻の連絡はできるようにする |
| 振替 | 授業を休む代わりに、他の同じ授業実施日（別の授業クラス・別日程の同内容の授業）に出席すること |
| 30分前補講 | 授業を休む代わりに、次回以降の授業に30分早く来て、前回休んだ分＋当日の授業を受けること。次回が、生徒本人が所属する授業クラスの回（次週など）である場合と、別の授業クラスの回に参加する場合の両方があり得るが、システム上は「補講として出席する対象の授業回を選ぶ」という共通の仕組みで扱う |
| 会員番号 | 保護者に発行するログインID。生徒登録時に運営が採番する。生徒本人ではなく保護者単位で発行し、1保護者に対して複数の生徒（兄弟など）を紐付けられるようにする |
| 休会 | 生徒が一時的に授業を休むこと（例：長期休暇中の一時休会）。生徒ごとに休会開始月を設定でき（終了月は任意）、その期間は出席記録・一覧画面の対象外となる。終了月を設定しない場合は再開の連絡があるまで休会が継続する。月謝が月単位のため、入力は年月単位で行い、保存時に開始月の1日／終了月の末日に変換する。授業クラスの定員（6名）としては引き続きカウントする |

## 5. 機能要件（MVP）

### 5.1 運営向け機能

- スタッフ（運営）の登録・編集・論理削除（権限区分：出席管理のみ行える権限／出席管理＋生徒・保護者の登録も行える権限）
- 保護者の登録・編集・論理削除（登録時に会員番号と初期パスワードを発行）
- 保護者のパスワード再発行
- 生徒の登録・編集・論理削除（1保護者に対して複数の生徒を紐付け可能。氏名・学年・所属する授業クラスを管理。登録時、所属する授業クラスの定員（6名）を超えないか確認する。休会期間（開始月・終了月〈任意〉）も設定可能）
- 出席記録の登録・編集・削除（授業クラス・授業回ごとの一覧画面から記録。通常出席／遅刻／欠席／振替済み／30分前補講済み／未定、のステータスを扱う。休会期間中の生徒は対象外とする）

### 5.2 保護者向け機能

- メールなど基本情報の登録・編集、パスワード再設定（初回ログイン時に発行された会員番号・初期パスワードでログインし、メールアドレスを登録することで、以降はメールによるセルフサービスのパスワード再設定が可能になる）
- 欠席・遅刻の情報登録（複数の生徒〈兄弟など〉をまとめて連絡可能。画面の選択肢にない内容を伝えたい場合のため、任意の自由記入欄も用意する）
- 欠席時の振替・30分前補講の情報登録（欠席連絡と同時に、補講方法を「振替」「30分前補講」「未定（運営が後日対応）」から選択。決める場合は対象の授業回まで指定する）
- 出席履歴・予定の確認（時系列リスト形式。次回の授業予定を上部に表示し、過去の出席履歴を新しい順に一覧表示）

### 5.3 運営・保護者共通の機能

- ログイン機能（会員番号／パスワードによる認証）

## 6. 非機能要件

- バックエンド：Laravel／フロントエンド：React（Inertia.jsを使用したLaravel＋React構成）
- ローカル開発環境はDockerで構築
- CI/CDツールを導入（GitHub Actionsを想定）
- 本番環境にデプロイし、外部からアクセス可能な状態にする（デプロイ先：**Render（Web Service）＋Neon（PostgreSQL）の組み合わせ**。ともに無料枠を利用。詳細は実装ロードマップPhase 6参照）
- 公開する実データはダミーデータのみとし、実際の教室名・生徒の個人情報は使用しない

## 7. 対応デバイスと開発優先順位

運営・保護者ともにスマホでの利用が多いと想定されるため、スマホ対応を優先する。

開発優先順位

1. 運営向けスマホサイト・保護者向けスマホサイト
2. 運営向けPCサイト
3. 保護者向けPCサイト

## 8. スコープ外・将来対応

- 保護者・生徒・スタッフの詳細画面
- 保護者が「補講未定」の情報を後から自分で編集できる機能
- 休みマスタ管理機能（最初はSeederで登録する）
- 授業クラスマスタ管理機能（最初はSeederで登録する）
- 授業回マスタ管理機能（最初はSeederで登録する）
- 運営向けPCサイト
- イベント案内機能
- 保護者向けPCサイト
- 仮ID・仮パスワードをまとめた登録案内用紙を生成する機能
